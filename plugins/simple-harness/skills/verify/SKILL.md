---
name: verify
description: '"확인해줘", "다 된 거 맞아?", "verify" 또는 기능 완성 시 실제로 실행해 검수하고 직접 고친다.'
---

1. `docs/CONTEXT.md`의 완료 조건과 이번 요청에서 눈으로 확인할 동작 3~7개를 정한다.
   완료 조건이 비었으면 추론해 적는다.
2. 가능하면 별도 Agent에게 기준과 실행 방법만 넘겨 검수한다. 아니면 작성 과정을
   모르는 사용자처럼 직접 한다.
3. 실제로 실행해 확인한다.
   - 화면: 쓸 수 있는 브라우저 도구(예: Playwright)로 사용자처럼 조작한다. 프로젝트에
     브라우저 테스트가 있으면 실행한다. 백엔드가 있으면 화면 동작 뒤 데이터가 실제로
     저장됐는지 API·DB로 확인한다. 도구가 없으면 설치하지 말고 화면은 미검증으로 둔다.
   - 서버·API: 서버를 띄우고 실제 HTTP 요청을 보내 상태 코드·응답·저장·잘못된 입력·
     권한 없음·서버 로그를 본다.
   - 명령줄·라이브러리: 실제 입력으로 실행하거나 자동 테스트와 짧은 사용 예를 돌린다.
   - 공통: 정상 흐름, 빈 값·잘못된 입력, 재시작 후 데이터 유지, 쉬운 오류 메시지.
     외부를 바꾸는 동작(결제·메일·운영 데이터)은 승인 범위나 테스트 값으로만 한다.
4. 실패하면 묻지 않고 고친 뒤 다시 확인한다. 같은 문제가 세 번 고쳐도 남으면 멈추고 알린다.
5. 띄운 서버·브라우저와 검수 중 생긴 임시 파일을 정리한다.
6. 동작마다 ✓/✗ 한 줄(코드·파일 위치 없이), 고친 것, 미검증과 이유를 쓴다. 끝에 사용자가
   코드 없이 해볼 확인 2~3개를 "○○하면 ○○가 보여야 합니다"로 준다. 없으면 생략한다.
   화면이 미검증이면 브라우저 도구를 설치하면 화면까지 검수할 수 있다고 한 줄 덧붙인다.
7. 결과를 `docs/CONTEXT.md`의 최근 결과에 반영한다.
