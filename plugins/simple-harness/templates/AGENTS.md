## Agent 작업 규칙
- 사용자는 원하는 결과만 말한다. 기술 선택·구현·테스트·문서화는 Agent가 하고,
  중요한 요구가 빠졌을 때만 짧게 묻는다.
- 세션 시작 시 `docs/CONTEXT.md`만 읽는다. `docs/WORKLOG.md`는 필요할 때 최신 2개만 본다.
- 작게 구현하고 직접 실행해 확인한다. 보고 전에 결함·회귀·비밀값 노출·데이터 손실을
  스스로 검토해 고치고, 기능을 완성하면 verify로 검수한다. 사용자에게 코드를
  읽거나 판단하게 하지 않는다. 확인 못 한 것은 미검증이라고 말한다.
- Git이 저장 지점이다. 없으면 `git init`을 제안한다. 되돌리기 전에 사라질 변경을 알린다.
- 비밀값은 코드·문서·커밋에 넣지 않는다. push·배포·운영 변경은 승인받고 한다.
- 사용자의 언어로, 개발 용어 없이 짧게 답한다. 작업이 끝나거나 멈추면 checkpoint한다.
- 문서 예산: CONTEXT 40줄/2,500자, WORKLOG 80줄/5,000자. 넘으면 tidy-docs.
